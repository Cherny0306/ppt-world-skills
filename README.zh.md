# ppt-world-skills：通用结构化PPT生成（Pitch / Research / 混合型）

> 适用：把任何项目/研究/产品/平台能力，快速生成**结构化PPT输出**（可直接用于做幻灯片）。  
> 支持类型：**Pitch（路演/立项/融资/争取资源）**、**Research（研究汇报/学术/课题）**、**Hybrid（业务+研究混合型）**、**Update（进展周报/月报/里程碑）**。  
> 输出：`PPT逐页结构（标题+要点+图表建议+讲稿要点）` + `可复用的一页纸摘要` + `风险/下一步/请求支持（如适用）`。  
> 核心原则：**结论前置、信息分层、受众导向、可视化优先、可复用模板**。

---

## 1. 输入信息（统一采集表）

> 经验法则：信息不全也能写，但至少要有“目标 + 受众 + 现状/证据”。  

### 1.1 基本信息（必填）
- 主题/项目名称：
- PPT类型（选一）：Pitch / Research / Hybrid / Update
- 受众（选一或多选）：领导/管理层｜业务部门｜技术团队｜客户/合作方｜评审专家
- 汇报时长：5/10/20/30分钟（或页数上限）
- 你希望听众最后做什么决定：立项/给资源/批准试点/合作/继续研究/通过评审等

### 1.2 内容素材（至少填2项）
- 背景与问题（痛点/机会/研究问题）：
- 方案/方法（做法、路线、关键模块）：
- 进展与证据（demo、数据、实验结果、客户反馈、测试情况）：
- 价值与影响（节省成本、提升效率、风险降低、学术贡献、社会影响）：
- 风险与边界（合规、技术不确定性、依赖项、数据问题）：
- 下一步计划与资源需求：

### 1.3 可选增强信息（能显著提质）
- 竞品/对标/相关工作（研究/行业/同类产品）：
- 目标用户画像/典型场景/客户清单：
- 指标体系（KPI/实验指标/验收标准）：
- 预算口径（大致区间或资源清单即可）：
- 图表/流程图/样例图片（可上传）：

## 1.4 触发时自动提问（Agent Clarifying Questions）

> 目的：当用户信息不全或存在多种合理解释时，Agent应**先用少量高影响问题补齐关键槽位**，再生成PPT结构化输出，避免返工。  
> 建议实现：在Skill被触发后，先检查“必填槽位”，缺失则调用 AskUserQuestion（1次最多4问），按下述顺序提问。

### 1.4.1 槽位检查规则（先检查这些）

**A. 通用必填槽位（缺一则必须问）**
1. PPT类型：Pitch / Research / Hybrid / Update  
2. 受众：领导/管理层｜业务｜技术｜客户｜评审  
3. 时长或页数上限：5/10/20/30分钟（或页数）  
4. 期望决策/行动：立项/给资源/批准试点/合作/通过评审/仅同步进展

**B. 类型必填槽位（按类型缺一则必须问）**
- Pitch：Ask（希望领导支持什么）+ 价值量化口径（至少1–2个指标或目标）  
- Research：研究问题/目标 + 数据来源/实验设置 + 评价指标  
- Hybrid：决策目标（Ask）+ 可信性证据（数据/评测/人审/案例）  
- Update：汇报周期 + 本期结论（3条）+ 阻塞与需要支持

**C. 可默认槽位（缺失可先假设，不必问）**
- 视觉风格（科技风/政务风/简洁风）→ 默认“简洁政务风”  
- 页内图表偏好 → 默认“流程图+对比表+时间轴”三件套  
- 是否需要Q&A页 → Pitch/Hybrid默认附1页

### 1.4.2 提问优先级（只问最关键的）

1. **先问类型与受众**（决定结构骨架与语言风格）  
2. **再问时长/页数与决策目标**（决定信息密度与结尾“Ask”写法）  
3. **再问证据与指标**（决定可信性与价值量化的写法）  
4. **最后问可选增强项**（竞品/预算/风格），能不问就不问

## 1.5 自动提问题库（可直接用于 AskUserQuestion）

> 使用方式：根据缺失槽位，从下列题库中挑选 1–4 个问题组成一次 AskUserQuestion 调用。  
> 注意：每题选项尽量互斥、语言简短；推荐选项放第一并标注“(Recommended)”。

### 1.5.1 通用首轮（优先问这组）

**Q1（类型）**：你希望这份PPT属于哪种类型？  
- Pitch（Recommended）：争取支持/立项/合作/资源  
- Research：研究/课题/学术汇报  
- Hybrid：业务价值 + 方法可信混合  
- Update：阶段进展/周报月报

**Q2（受众）**：主要听众是谁？  
- 领导/管理层（Recommended）  
- 业务部门/客户  
- 技术团队/研发  
- 评审专家/学术场景

**Q3（时长）**：预计汇报多长时间？  
- 10分钟（Recommended）  
- 5分钟（电梯版）  
- 20分钟（标准版）  
- 30分钟（完整评审版）

**Q4（决策/行动）**：你希望听众最后做什么？  
- 批准试点/立项（Recommended）  
- 给资源/预算/机制支持  
- 同意合作/签约  
- 仅同步进展/收集反馈

### 1.5.2 Pitch/Hybrid专用（补“Ask”与价值口径）

**Q（支持类型）**：你希望在最后一页“请求支持”具体要哪三类支持？  
- 立项定位 + 协同机制 + 最小资源包（Recommended）  
- 经费 + 算力/服务器 + 数据/权限  
- 试点场景授权 + 部门配合 + 对外合作背书  
- 其他（将由用户补充）

**Q（价值主轴）**：这份PPT最想突出哪类价值？  
- 提效降本（Recommended）  
- 风险前移/合规审计  
- 业务增量/对外服务产品化  
- 品牌影响力/示范意义

### 1.5.3 Research专用（补实验设置）

**Q（研究重心）**：你希望PPT重点呈现哪部分？  
- 方法与实验结果（Recommended）  
- 相关工作综述与差异点  
- 数据集与标注体系  
- 讨论与局限/未来工作

**Q（结果成熟度）**：当前结果处于什么阶段？  
- 已有可展示主结果（Recommended）  
- 只有初步实验/小样本  
- 只有方法设计/尚未实验  
- 正在复现/对比中

### 1.5.4 Update专用（补进展口径）

**Q（汇报节奏）**：这是哪种进展汇报？  
- 本周/本期进展（Recommended）  
- 本月进展  
- 阶段里程碑复盘  
- 临时专项通报

## 1.6 路由功能（Deck Router）

> 作用：当用户未明确PPT类型/时长/受众时，Agent应依据输入信息**自动选择最佳结构骨架**，并自动设定页数与信息密度。  
> 原则：宁可先路由到“能决策”的版本（Pitch/Hybrid），也不要直接输出细碎材料导致领导听不懂。

### 1.6.1 类型路由规则（从上到下匹配，命中即用）

1. **Update路由**：用户明确是“周报/月报/进展同步/里程碑复盘”，或目标是“同步进展、排障、要支持”。  
2. **Pitch路由**：用户目标是“争取支持/立项/审批/资源/合作”，且受众偏管理层；强调价值与决策。  
3. **Research路由**：用户目标是“学术/课题/评审/结题”，内容包含实验设计、指标、结果对比；受众偏评审专家。  
4. **Hybrid路由（默认优先）**：同时满足“要决策/要落地”且需要“方法可信/证据链/评测”；或受众既有管理层也有技术/评审。  

> 快速判断口诀：  
> - “要拍板”→ Pitch / Hybrid  
> - “要评审”→ Research  
> - “要同步进展”→ Update  
> - “既要拍板又要证明”→ Hybrid

### 1.6.2 受众路由（决定语言层级）

- **领导/管理层**：管理语言优先（价值、风险、机制、验收），技术细节≤20%  
- **评审专家**：方法与证据优先（实验、对照、指标、消融/误差分析）  
- **业务/客户**：场景与收益优先（流程变更、可交付物、服务模式、成本收益）  
- **技术团队**：架构与实现优先（模块、接口、依赖、数据治理、工程计划）  

### 1.6.3 时长/页数路由（默认值）

- 5分钟：5–7页（电梯版，只保留结论与Ask/下一步）  
- 10分钟：8–10页（标准决策版）  
- 20分钟：12–16页（可讲清方案与路径）  
- 30分钟：16–24页（评审/完整版本）  

### 1.6.4 成熟度路由（决定“证据”呈现深度）

- **有主结果/可演示**：必须包含“Demo/案例页 + 指标页 + 误差/风险页”  
- **只有小样本/早期实验**：强调“试点设计 + 验收指标 + 风险控制”，避免过度承诺  
- **只有方案设计**：强调“为什么这样设计 + 最小可行试点（MVP）+ 里程碑与资源需求”

## 1.7 决策树流程化（Decision Tree Workflow）

> 作用：把Skill执行过程“流程化、可复用、可自动化”。  
> 输出要求：每次执行都走同一套流水线，保证质量稳定。

### 1.7.1 决策树（文本版）

```
开始
 ├─(1) 采集输入（1.1~1.3）
 ├─(2) 槽位检查（1.4.1）
 │    ├─缺失关键槽位？→ 是：AskUserQuestion（≤4问）→ 回到(2)
 │    └─否
 ├─(3) 路由选择（1.6）
 │    ├─判定类型：Pitch / Research / Hybrid / Update
 │    ├─判定受众语言层级
 │    └─判定时长→页数与密度
 ├─(4) 选择结构骨架（第2章对应骨架）
 ├─(5) 生成“一页纸结论”（Why/What/Proof/Value/Ask）
 ├─(6) 逐页生成（第3章交付格式：每页≤3要点+视觉+讲稿）
 ├─(7) 插入关键可视化（至少：流程图+对比表+时间轴）
 ├─(8) 质量检查（第7章清单）
 │    ├─不通过→回到(6)微调
 │    └─通过
 └─输出最终结构化PPT
结束
```

## 2. 选择PPT类型的“结构骨架”

> 先选骨架，再填内容；同一素材可快速切换不同类型PPT。

### 2.1 Pitch（路演/立项/争取资源）骨架

**目标**：让决策者“相信方向、看到价值、认可路径、当场拍板/给资源”。  

推荐页数：10分钟 8–10页；20分钟 12–16页。

必含模块（按顺序）：
1. 封面（标题+一句话定位）
2. 一页纸结论（Why/What/Value/Ask）
3. 问题与窗口期（痛点、趋势、为什么现在）
4. 解决方案（一句话+架构图/流程图）
5. 核心亮点（差异化、护城河、关键能力）
6. 价值量化（KPI/ROI/效率提升/风险降低）
7. 落地路径（里程碑+试点范围+验收标准）
8. 风险与对策（让领导放心）
9. 请求支持（3件事：定位/机制/最小资源包）
10. Q&A备用页（常见问题与口径）

### 2.2 Research（研究汇报/课题/学术）骨架

**目标**：证明“研究问题清晰、方法严谨、结果可信、贡献明确”。  

推荐页数：20分钟 12–18页；30分钟 16–24页。

必含模块：
1. 标题页（题目+作者/单位+日期）
2. 摘要页（贡献点/主要结论/关键结果一页讲清）
3. 背景与相关工作（现状、缺口、研究问题）
4. 研究目标与假设/定义（指标、约束、数据范围）
5. 方法概述（总体框架图）
6. 方法细节（关键模块1–3页：算法/模型/流程/实验设计）
7. 数据与实验设置（数据来源、划分、评价指标、对照组）
8. 结果（主结果图表：表格/曲线/消融/对比）
9. 分析与讨论（误差分析、案例、失败模式）
10. 结论与展望（局限性、下一步、可复现材料）

### 2.3 Hybrid（业务+研究混合型）骨架（推荐给“技术平台/AI系统”）

**目标**：既要“讲清价值与落地”，也要“讲清可信与方法”。  

推荐页数：20分钟 14–20页。

模块顺序建议：
1. 封面
2. 一页纸结论（决策版：Why/What/Value/Ask）
3. 背景痛点（业务/行业/区域）
4. 需求与场景（典型客户/用户画像）
5. 方案总览（平台/系统架构）
6. 核心方法可信性（数据、知识库/规则、模型、评测）
7. Demo/案例（前后对比、证据链）
8. 价值量化（效率、成本、风险、质量）
9. 落地计划（里程碑+试点+验收）
10. 风险与治理（合规、审计、人审闭环）
11. 请求支持/合作方式

### 2.4 Update（阶段进展/周报月报）骨架

**目标**：让管理者快速掌握进展、风险与下一步。  

推荐页数：5–8页。

1. 本期结论（本周/本月3个结论）
2. 关键进展（按目标拆解）
3. 数据/指标（趋势图）
4. 风险与阻塞（需要谁决策）
5. 下期计划（里程碑）
6. 需要支持（明确到人/资源/时间）

## 3. “逐页结构化输出”格式（统一交付格式）

> 交付时必须按本格式逐页输出，方便直接迁移到PPT制作。

对每一页输出以下字段：
- **页码 & 标题**（一句话，偏结论）
- **本页目的**（让观众得到什么判断）
- **要点（≤3条）**（每条≤18字，尽量动宾结构）
- **建议图表/视觉**（流程图/对比表/象限图/时间轴/地图热力等）
- **讲稿要点（30–60秒）**（口播，先结论后解释）
- **可选备注**（数据来源/术语解释/备用说明）

## 4. 通用可视化组件库（按场景套用）

### 4.1 一页纸结论（任何类型都适用）
- Why（为什么）  
- What（做什么）  
- Proof（凭什么/证据）  
- Value（价值）  
- Ask（要什么支持/下一步）  

### 4.2 常用图表模板
- **2×2象限**：开源 vs 商业、短期 vs 长期、风险 vs 收益
- **对比表**：传统 vs 新方案（成本/效率/风险/覆盖）
- **流程图**：输入→处理→输出（强调可追溯/可审计）
- **时间轴/甘特图**：里程碑与交付物
- **漏斗图**：线索→试点→复制→规模化
- **证据链卡片**：结论 + 证据来源 + 相似案例 + 人审结果
- **KPI仪表盘**：覆盖、准确率、耗时下降、资产沉淀数量

---

## 5. 写作与表达规则（确保“在点上”）

### 5.1 结论前置（每页第一句话）
- 每页标题尽量是结论句，而不是主题句。  
  - 不好：`方案介绍`  
  - 好：`方案已具备试点条件，可小步快跑上线`

### 5.2 每页只服务一个判断
- Pitch：方向对不对 / 值不值得投 / 能不能做成 / 要我支持什么  
- Research：问题是否重要 / 方法是否新 / 实验是否严谨 / 结论是否可信  
- Hybrid：价值是否明确 / 可信是否足够 / 路径是否可落地

### 5.3 少术语，多“可决策语言”
优先使用：效率、成本、风险、合规、覆盖、验收、复制、机制、资源。

---

## 6. “常见页型”填充指南（快速写满一套PPT）

### 6.1 痛点页（Problem）
- 结构：现状 → 矛盾 → 后果  
- 可视化：三行对比/成本曲线/覆盖地图

### 6.2 方案页（Solution）
- 结构：一句话定位 → 三层架构（数据/能力/应用） → 一条主链路（流程图）

### 6.3 价值页（Value）
- 结构：内部价值（提效降本/控风险） + 外部价值（业务增量/影响力）  
- 必须量化：至少给3个可验收指标（哪怕先给目标值与口径）

### 6.4 路径页（Plan）
- 结构：里程碑（季度/阶段）+ 每阶段交付物 + 验收标准

### 6.5 风险页（Risk）
- 结构：风险列表（≤4条）→ 每条对策（人审闭环/证据链/数据治理/可替换策略）

### 6.6 请求支持页（Ask，仅Pitch/Hybrid/Update必需）
- 固定模板：  
  1）立项定位（战略/方向）  
  2）协同机制（跨部门/审核/数据权限）  
  3）最小资源包（算力/数据/人力/试点保障）

## 7. 质量检查清单（交付前自检）

### 7.1 结构是否匹配类型
- Pitch：是否有“一页纸结论”和“明确的支持请求”
- Research：是否有“相关工作+实验设置+结果分析”
- Hybrid：是否既有“价值”又有“可信性与治理”

### 7.2 信息密度是否合格
- 是否每页≤3要点且能口播
- 是否至少3个量化指标（KPI或实验指标）
- 是否给出里程碑与验收口径
